# ADR-0003: GitHub Wiki как двуязычная витрина

Статус: **принято**

Дата: **29 июля 2026 года**

## Контекст

Игрокам нужна публичная витрина аспектов JAZZ с конкретикой. Репозиторный `docs/wiki/` остаётся рабочим справочником и частью DoD агентов, но плохо подходит как единственная «лицо мода» на GitHub: один язык, путь внутри пакета, нет автопубликации на вкладку Wiki.

## Решение

- Канон витрины хранится в `docs/showcase/ru/` и `docs/showcase/en/`.
- GitHub Wiki репозитория `JAZZ` — опубликованная копия, не второй источник истины.
- Публикация идёт скриптом `scripts/docs/publish-github-wiki.ps1` и workflow на `main`.
- `docs/wiki/` и technical сохраняют роли ADR-0002; showcase пересказывает наблюдаемое поведение для читателя GitHub на RU и EN.
- Generated weapon catalog (`docs/wiki/weapons/*.md`) **зеркалируется** на GitHub Wiki при публикации; канон чисел остаётся CSV + генератор, не ручные правки wiki.
- Витрина (`docs/showcase`) ссылается на каталог; workflow публикует оба слоя.

## Альтернативы

- Только GitHub Wiki как канон — отклонено: ломает DoD, агентский контракт и CSV→wiki пайплайн оружия.
- Только GitHub Pages из `docs/` — отложено: Wiki уже включена и закрывает запрос «как вики GitHub»; Pages можно добавить позже без смены канона showcase.
- Зеркало всего `docs/wiki/` без EN — отклонено: нужна двуязычность витрины.

## Последствия

- Player-facing delta требует RU+EN страниц showcase, если затронут аспект витрины.
- Изменение оружейных чисел: CSV → `weapons-docs.mjs` → `docs/wiki/weapons/` → автопубликация GitHub Wiki (тот же workflow).
- Ручное редактирование страниц на github.com/…/wiki без обратного переноса в репозиторий запрещено контрактом.
- Документационный аудитор проверяет парность RU/EN и наличие `pages.json`.

## Связанные specs и системы

- ADR-0002
- `docs/showcase/`
- combat / weapons / strategy player docs

## Условия пересмотра

Решение пересматривается при переносе витрины на Pages/внешний сайт как единственный publish target или при отказе от двуязычного канона в репозитории.
