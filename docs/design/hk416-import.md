# HK416: модульная подготовка

Решение владельца: один предмет HK416 с модулями, не отдельные предметы по числу мешей. Кандидат установлен 2026-10-03; игровая приёмка не выполнена, запуск игры запрещён владельцем.

## Установленный кандидат и повторная проверка

Три длины ствола (D10/D14.5/D20), штатный/CTR приклад, STANAG 30 и пять существующих прицелов. Дополнительные цевья и рукояти пока не доступны. ID `HK416`; RU/EN экспортированы для трёх новых строк через канонический scoped exporter. Общий localization audit остаётся с чужими коллизиями; новый набор их не содержит.

Первое превью отклонено владельцем: неправильная ориентация/посадка магазина и странное сглаживание. MLOD reader не читал `#SharpEdges#`. Теперь авторские жёсткие границы сохранены разделением топологии, без custom normals; CO/NM не изменялись. Магазин в detached OBJ был перевёрнут по вертикали: прямой подающий участок находится у минимального Z, изогнутое дно — у максимального. Коррекция разворачивает его на 180° вокруг поперечной оси, сохраняет исходный размер и центрирует прямой участок в шахте. Окончательная посадка требует визуальной приёмки владельцем. Шесть compiled mesh/winding audits и девять Lua configuration checks проходят. Установка и коррекция имеют отдельные backup/receipt в `<WEAPON_SOURCE_ROOT>/_hk416_jazz_build/`.

RM — приближение legacy Super: R=G=(2/(100×gloss+2))^0.25, B=0 для окрашенной диэлектрической поверхности. Это не эквивалент исходного specular shader и не визуальный PASS. Проверить материалы, посадку магазина и прицелов в игре перед закрытием задачи.

## Полученный пакет

`<WEAPON_SOURCE_ROOT>/_weapon_import_20261003/hk416/`:
- `modules/HK416_modules_review.blend`: отдельная сцена геометрии с source_object и export_ready=false; 26 исходных мешей разделены на 1368 геометрических островов. Остров — не игровой модуль.
- `modules/model_*.png`: 26 отдельных обзоров исходных деталей.
- `modules/modules.json`: UV, геометрия, границы и происхождение островов; 0 геометрических ошибок и 0 custom normals после подготовки.
- `source-audit.json`: SHA256 архива/карт, состав 25 текстурных семейств, доказательства дублей и отсутствующих MTL.
- `source-tga/`: авторские CO/NOHQ/normal в uncompressed TGA. RGB roundtrip точный, gamma decode и инверсия нормалей не применялись.

## Доказанные дубли

- model_21 → model_25: идентичные UV; масштаб 99.9999996, поворот и перенос; максимальная ошибка совмещения 0.00000315 исходной единицы.
- model_11 → model_22: идентичные UV; масштаб 0.999999996, поворот и перенос; максимальная ошибка 0.000000042 исходной единицы.

Не предлагать эти копии как разные модификации. Источники сохранены.

## Материалы

В архиве 26 OBJ, каждый ссылается на отсутствующий model_N.mtl. Нет .blend/.fbx/.gltf или RVMAT. Нельзя доказать авторские назначения материала только по порядку файлов. Предыдущий atlas occupancy score оставлен подсказкой, не принят за binding.

Карты CO/NOHQ/AS со spec/gloss требуют восстановления исходного shader contract. Имена соответствуют соглашениям Bohemia, но этого недостаточно для применения glTF specular-gloss conversion: коэффициенты исходного шейдера не приложены. RM пока не генерировался.

Справка: [Bohemia texture naming](https://community.bistudio.com/wiki/Armed_Assault%3A_Texture_Naming_Rules), [Super shader](https://community.bistudio.com/wiki/Super_shader). AS использует G; specular/gloss нельзя объявлять metal/rough по одному имени.

## Продолжение

Первоначально запрошен исходник; затем самостоятельно найдены редактируемые авторские MLOD в NIArms. Проблема отсутствия сборки снята для восьми конфигураций. Игровые переключения модулей, HGE/AP, compiled winding/UV, итоговый RM, RU/EN и иконки ещё не реализованы.

## Восстановленная авторская сборка

[Исходный репозиторий NIArms](https://github.com/toadie2k/NIArms/tree/master/nia_wp_HK416), config.cpp и RVMAT. Совпадение UV-треугольников с локальными OBJ подтвердило материалы: model_1 common (980 совпадений), model_2 upper (545), model_3 lower (778), model_4 barrel (155), model_5 stocks (45); также одиночные upper/lower. Это доказательство происхождения bindings, не утверждение идентичности всех полигонов двух версий.

`assembled/HK416_authored_assemblies.blend` содержит восемь восстановленных конфигураций: 416C, D10, D14.5, D16.5, D20, D10 Geissele, D10 RAHG, D10 ST6. Оригинальные face texture/material и named selections прочитаны из MLOD. Разделены Body, Barrel, Stock, Muzzle и sights, где авторские selections существуют. При открытии включить нужную конфигурацию: варианты скрыты, чтобы не накладываться друг на друга. Магазин и дополнительный обвес в MLOD являются внешними proxy и требуют отдельной сборки.

`module-matrix.json` фиксирует комбинации-референсы. Варианты длин не равны обещанию свободного смешивания всех деталей: посадку смешанных комплектов ещё проверить. `assemblies.json` фиксирует границы, исключённые proxy и недостающие карты. В двух расширенных вариантах отсутствуют map2-556tan_co и gunfighter_tan_co; они отмечены явно, не подменены чужими картами. Шесть остальных сборок имеют все используемые diffuse-карты.

Превью сейчас показывает diffuse с постоянной roughness=0.65; это **не финальные материалы JA3**. Исходный Super shader использует specularPower и Fresnel: простой инверсии gloss недостаточно для точного переноса бликов. RM не выдаётся за готовый.

`_read_hk416_mlod.py` читает первый редактируемый P3DM LOD и named selections по [формату Bohemia](https://community.bistudio.com/wiki/P3D_File_Format_-_MLOD). `_assemble_hk416_reference.py` собирает сцену, исключает proxy, сохраняет UV, пересчитывает геометрические нормали без custom layer и удаляет только выявленные нулевые/вырожденные грани. Нормали из файла не импортируются как split normals. Архив владельца неизменён.
