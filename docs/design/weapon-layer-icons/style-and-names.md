# Единый стиль и названия значимых конфигураций

Дополнение владельца к JAZZ-WEAPON-ICONS-001. Это контракт и offline-прототип; игра не изменена.

**Обновление 28.09.2026:** live-съёмка и делегированное self-review описаны в [live/SDD.md](live/SDD.md). Это актуальное уточнение первоначального контракта ниже: M4 20-round magazine действительно прямой; StockLightFolded/UnFolded у AK74 визуально соответствуют сложенному/раскрытому прикладу; **кандидат СВДС отклонён** для установленной цельной thumbhole-ложи. Указания «ждёт съёмки» ниже относятся к предыдущему offline-этапу. Правило СВДС остаётся disabled; production-интеграции нет.

## Один стиль на весь арсенал

Старое и новое оружие проходит один процесс съёмки/обработки. Нельзя смешивать нарисованные старые иконки и реалистичные новые снимки как окончательный результат. Стиль: узнаваемые материалы реальной игровой модели, чистый боковой силуэт, сдержанные блики, единый тёмный внешний контур, прозрачный фон. Существующий M4 demo проверяет механизм; его свет и контур не считаются окончательно утверждённым эталоном.

| Параметр | Общее правило |
| --- | --- |
| Ракурс | Одинаковая сторона оружия, дуло вправо; фиксированный боковой вид без индивидуальных наклонов |
| Камера | Ортографическая либо фиксированный согласованный capture-профиль, если API не предоставляет orthographic; результат сравнивается по пропорциям |
| Свет | Один сохранённый набор света, экспозиции и цветового профиля; без погодного/секторного света и индивидуального auto exposure |
| Цвет | Материалы из игры; одна обработка, без произвольной перекраски и разной насыщенности для новых/старых моделей |
| Масштаб | Фиксированные профили pistol / long gun / heavy; внутри семейства и при переключении модулей масштаб не меняется |
| Кадр | Общий anchor и поля; кадр рассчитывается на максимальную поддержанную сборку. Не растягивать короткий ствол до длины длинного |
| Alpha | Настоящая прозрачность, без белой/цветной каймы; итог проверяется на светлом и тёмном фоне |
| Контур | Один внешний контур объединённого силуэта. Пробный размер 2 px в 324×165; выбрать эталон до массовой обработки, затем зафиксировать |
| Детализация | Проверять итоговый размер в UI, а не только крупный рендер; оптика, магазин и приклад должны читаться |
| Охват | До включения оружия в каталог проверить штатную, короткую, длинную и наиболее навесную доступные сборки |

До серии снять лист из старого АК-74, M4A1, СВД, пистолета и пулемёта одним профилем. Владелец принимает этот лист как общий художественный эталон. Затем распространяем процесс на весь реестр, без отдельного стиля для каждого семейства. Камерные профили различаются только фиксированным масштабом/кадром, а не направлением света и характером обработки. Для пулемёта, помещающегося в long-gun кадр, отдельный heavy масштаб не нужен.

## Значимое изменение имени

Имя выбирается по явной таблице **class + host + значимая конфигурация**, а не по любому отличию от дефолта. По мере охвата допускаются комбинации Stock/Barrel/Body/Caliber, когда они представляют узнаваемую версию и соответствуют реальной модели. Компонентное имя вроде StockLight само по себе не основание для переименования всего оружия.

| Конфигурация | Результат | Статус |
| --- | --- | --- |
| AK74 + JAZZ_StockNormal | АК-74 / AK-74 | Проверено offline |
| AK74 + JAZZ_StockLightUnFolded | АКС-74 / AKS-74 | Проверено offline |
| AK74 + JAZZ_StockLightFolded | АКС-74 / AKS-74 | То же семейство, только положение приклада |
| Возвращён штатный приклад AK74 | Снова АК-74 | Проверено на том же экземпляре |
| Другой прицел/магазин/дульник/подствольник | Прежнее структурное название | Сам по себе такой обвес не переименовывает оружие |
| AK74M со складным прикладом | Собственное исходное имя | Не превращать в АКС-74 по общему ID приклада |
| DragunovSVD + JAZZ_StockLight | Кандидат СВДС / SVDS | Отключён до съёмки и проверки конфигурации |
| Именной/уникальный вариант | Своё имя | Нет общего правила, стирающего уникальные имена |

У AK74 текущие visuals складного семейства — AK74StockUnFld / AK74Stockfld. По названиям файлов их положения выглядят противоположными суффиксам component IDs; это нужно проверить при съёмке. Правило названия от положения не зависит, поэтому не опирается на расшифровку этих суффиксов.

У DragunovSVD лёгкий приклад отображается через **WeaponAttA_StockDragunov_03**; обычный — **WeaponAttA_StockDragunov_02**. Пока не подтверждено, что первая игровая сборка действительно представляет СВДС. [Описание производителя](https://t.me/s/kalashnikovnews?before=4535) отличает рамочный складной приклад и отдельную пистолетную рукоятку. Поэтому пока сохранено предложение владельца как кандидат, без автоматического отождествления любого облегчённого приклада с СВДС. Если съёмка подтверждает нужную конструкцию, включаем правило; иначе задаём точное название фактической конфигурации.

## Реализация и интеграция

[names.json](names.json) содержит явные правила и черновые RU/EN labels. [names.lua](../../tools/weapon_layer_icons/names.lua) возвращает представление имени, не меняя class, DisplayName, экземпляр, цену, баланс, loot или save state. При неизвестном host/модуле, неоднозначных правилах или отсутствии перевода возвращается исходное имя. Nil-slot берёт default; пустая строка/false означает пустой слот и не получает default по ошибке. Состояние оружия читается заново, поэтому обратная замена восстанавливает имя.

У будущих правил должна быть одна полная структурная конфигурация; при конфликте двух правил прототип оставляет исходное имя вместо случайного выбора. Оптика и навесные аксессуары не входят в условия текущих правил. Изменения внешнего вида и имени должны использовать один проверенный снимок итоговых components, но название не зависит от наличия PNG: временный fallback картинки не отменяет имя.

Одного метода GetDisplayName недостаточно считать интеграцию законченной: например, `Code/System_UnitInventory.lua` читает `item.DisplayName` и `DisplayNamePlural` напрямую для сообщений. Перед установкой требуется аудит tooltip, кабинета, inventory/HUD, магазина, сообщений, сравнения и plural; записи catalog без экземпляра показывают имя штатной конфигурации. Существующие хуки менять в их текущих точках, без нового setter wrap. Проверить clone/preview, возврат к дефолту, load/reload и изменение компонентов в открытом UI.

Черновые JSON labels не являются зарегистрированной локализацией. При production-интеграции применять manage-jazz-localization, выделить T IDs и синхронизировать RU/EN по правилам проекта. Здесь localization/generated/runtime файлы не менялись.

Проверка: `python docs/tools/weapon_layer_icons/test_names.py`. Она читает актуальные AK74/DragunovSVD companions и проверяет IDs/host, оба положения приклада, обратный переход, все доступные неструктурные модули AK74, неизвестные данные, plural и отсутствие мутации. Результат — [names-verification.json](names-verification.json).
