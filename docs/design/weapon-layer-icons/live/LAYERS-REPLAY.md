1. Export a fresh effective `catalog.lua` from JA3Debug on ModEditor. Exclude disabled classes with `content_scope.py`; exclude service objects DebugAuto and UnderslungGrenadeLauncher.
2. Run `dispatch_capture.py --catalog <catalog> --output <batch> --variants all --layers --matte`. If inventory pause is present, add `--resume-inventory-pause`. One camera batch at a time. Do not reload game code or take competing screenshots.
3. `capture-report.json` must finish with `phase=done`, no failed rows, restored camera/light/render/pause and disposed temporary objects. `reused-layer` points to a photograph with the identical native signature, not a synthetic attachment.
4. Run `audit_native_graphs.py --catalog <catalog> --output <graphs>` for native pairwise and dense configurations. It creates and disposes temporary clones without screenshots or camera changes. `complete_capture.py --catalog <catalog> --captures <batch> --graphs <graphs> --output <supplement> --wait --dispatch` waits for the initial camera job, then covers the missing signatures with a finite supplement. Alternatively, `plan_dependencies.py` and `run_dependencies.py` support explicit parent contexts. Never run both supplement paths simultaneously.
5. `compile_layers.py --catalog <catalog> --captures <batches...> --graphs <graphs> --output <library>` extracts transparent parts in the same image coordinate system and applies the fixed v3 weapon color profile. Keep mounts as separate native spots. Resolve all build report issues. The shared `capture_settings.py` camera profile must match photography and graph audit. After changing a family camera, refresh its graphs and photograph the whole family at that distance; do not mix coordinates. Observed context-specific geometry omissions are recorded as exact component-state overrides (for example the native SW Model 10 short barrel has no side attachment geometry).
6. `test_layers.py --registry <library>/registry.json --captures <batches...> --graphs <graphs> --output <library>/tests.json` checks native graph identity and slot combinations. Cartesian counts include potentially incompatible configurations; report those separately, never call them all valid builds.
7. Verify draw order against native photographs with multiple simultaneous modules. `review_layers.py` supports small pilots; `review_registry.py --optimize` fits a consistent order to reference photographs for each weapon and writes native/composed review sheets. A good isolated part does not prove correct occlusion in every assembly.
8. Run `test_layer_binder.py` and the disposable live `probe_layer_binder.py` before installing. The latter copies only selected layer textures, creates and deletes a temporary XImage, and leaves loaded UI hooks untouched.
9. `install_layers.py --library <library> --repo <core> --backup <backup-file>` preserves unrelated InventoryUI code and replaces only the marked local layer block and existing binder call sites. Test evidence is required. Verify inventory and weapon displays visually, including A → B → A changes, nil context, disabled tint, missing artwork fallback and closing windows.
10. Inspect `UIWeaponDisplay` with `inspect_templates.lua`. `editor_transaction.py` backs up tracked Lua files, verifies completed capture receipts, and invokes the official editor save through `edit_template_bindings.lua` to add the binder to both weapon callbacks. Review the resulting generated-file diff and reload roundtrip; do not reapply blindly if the save reloads Lua before writing its receipt.
11. Run `probe_installed_ui.py` only after all capture jobs finish and the installed binder is loaded. It photographs the real inventory and disposable combined-build XImages, removes temporary items/windows and restores inventory pause. Review those screenshots before accepting the runtime result.

All raw captures belong in a designated capture directory outside Git. Keep review evidence and reproducible tools in the repository. Do not mark the spec implemented until arsenal coverage and runtime visual acceptance pass.

Tone v4: run `calibrate_layers.py` with the current catalog and complete capture directories before `compile_layers.py`; it writes `layer-color-profiles.json` and an original/previous/smooth comparison. `test_layer_tone.py` checks that all 1928 visible layers preserve alpha and dimensions against the prior installation. One shared smooth curve per weapon avoids per-module exposure differences. Keep the already verified layer order during a tone-only rebuild.

After editor save, `normalize_editor_save.py` keeps the intended callback changes and officially generated revision/time/hash, archives post-save output and restores unrelated baseline serialization and load order. Use `reload_layers.py` to load the normalized source and verify the callbacks again. Texture refresh is limited to named test families; fresh windows request remaining textures on demand. The full catalog must not be preloaded into GPU memory.
