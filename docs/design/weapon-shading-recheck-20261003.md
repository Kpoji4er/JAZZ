# Повторная проверка сглаживания оружия

Владелец отклонил первое превью HK416: магазин перевёрнут вверх ногами и смещён, металл выглядит неправильно. Также указал на плоский вид R4 и VZ58. Игру не запускать; offline evidence не считать игровой приёмкой.

## Найдено

- HK416: при восстановлении MLOD пропускался `#SharpEdges#`; это стирало авторские жёсткие границы. Reader/assembler теперь сохраняет их топологией без custom normals. После повторного экспорта широкие ложные блики на планках и цевье уменьшились. Normal/CO карты неизменны.
- HK416 magazine: minimum source Z — прямой подающий участок, maximum Z — изогнутое дно. Ошибочно считали максимум Z верхом. Разворот 180° вокруг поперечной оси, центрирование подающего участка; после дополнительного замечания владельца посадка углублена на 12 мм до Z=0.102 в frame оружия. Исходный размер сохранён. Установлено с backup-2; игровая приёмка глубины ещё нужна.
- R4/VZ58: декодированы фактически установленные DDS металлического корпуса. NM XY RMS относительно исходника: 0.99863 / 0.99943. Средняя ошибка XY: 0.91 / 0.33 из 255. Ослабление нормалей в этих установленных картах не сохранилось.
- R4/VZ58: средняя ошибка roughness 1.73 / 1.64, metallic 1.31 / 0.45 из 255; соответствует исходникам с потерями DDS. Это не подтверждение правильного tangent basis.
- В одинаковом Blender освещении старых source blend широкие искажённые блики остаются с отключённой normal map. Однако эти blend не точно воспроизводили установленную геометрию: повторный VZ58 split 40° дал побайтно тот же HGM, что уже установлен. Это локализует риск сглаживания, но не доказывает причину плоскости текущего VZ58. Контрольные рендеры не воспроизводят JA3 renderer.
- Source OBJ audit при снятии imported custom normals: R4 7.62% corner normals меняются более чем на 10°, VZ58 3.51%. Это локализация риска, не доказательство ошибки всех перечисленных углов. Нормали не восстанавливались и материалы R4/VZ58 в этом проходе не менялись.
- Повторный read-only DDS audit прежних семейств: 112 entity, 111 материалов, 201 map binding. Один флаг `JAZZ_M14_MkIII_Norm.dds`: более 5% XY-векторов выходят за unit disk; требует отдельной проверки кодировки/источника. Этот audit не охватывает новую ветку HK416 и не является визуальным PASS остального оружия.

## Дальше

### Уточнение после сообщения «у HK416 нормали вывернуты в игре»

- Read-only `_audit_hk416_authored_normals.py` сравнил геометрические направления с авторскими P3DM normals, без импорта custom layers. Сопоставлены 18096/17975/18957 треугольников трёх корпусов, 812/3362 прикладов. Противоположные направления: по 8 на корпус, 0 на прикладах; по 11 треугольников корпуса не сопоставлены. Общий переворот граней этим не подтверждён. Магазин из отдельного OBJ этим аудитом не охвачен. Отчёт `authored-normal-direction-audit.json` в HK build.
- Normal map HK416 пока не инвертирована. Этот аудит не проверяет tangent basis/каналы NM в игровом шейдере. Нужен игровой кадр с конкретным дефектом; успешный compile не закрывает жалобу владельца.
- АЕК: применён ранее подготовленный `_aek_color_fix_20261003/manifest.json`: 3 BaseColor DDS + 3 fallback. Исправлена повторная sRGB-декодировка, затемнявшая исходный цвет. 44 защищённых ресурса и привязки материалов не менялись. Установка подтверждена, игровой результат ещё не подтверждён.
- R4/VZ58: кандидаты с авторскими жёсткими границами и узкой фаской сохранены в `_weapon_shading_20261003`. R4 bevel остаётся отклонён: AssetsProcessor сообщает два `normals with 0 length`, хотя явные FBX normal vectors ненулевые. Очистка микротреугольников/UV проблему не устранила. Кандидаты **не установлены**, gate не ослаблен; плоскость не объявлять исправленной.

Для R4/VZ58 сверить жёсткие границы, исходное сглаживание и mesh/bake compatibility; подготовить A/B геометрии при неизменных DDS. Не сглаживать и не усиливать normal maps ради сокрытия дефекта. Остальное оружие не объявлять визуально проверенным по одному DDS/compile audit.

## Игровая обратная связь и исправление HK416

Владелец подтвердил: «R4 и vz58 стали выглядеть лучше» — human appearance PASS для установленной коррекции сглаживания; это не проверка всех конфигураций. Последующие скриншоты HK416 показали пропадание наружных панелей, включая приклад. Прежний вывод по совпадению с авторскими normals был недостаточным: он не доказывал физическую наружную сторону. В MLOD assembler отражение Y/Z сочеталось с лишним разворотом corners; теперь порядок corners/UV сохраняется до outward recalc, открытые поверхности сохраняют исправленную сторону. Контроль нижней коробки: раньше 26 из 334 выбранных боковых граней смотрели наружу, теперь 308 из 334; выборка содержит также внутренние поверхности и не требует 100%. Магазин: все 493 выбранные боковые грани наружу, его геометрия не переворачивалась. `_check_hk416_exterior.py` проверяет три корпуса и магазин.

HK416 asset-refresh-backup-3: установлены шесть перекомпилированных деталей и новые иконки; 64 DDS/fallback побайтно сохранены. Scope/Mount опущены на 20 мм до измеренной rail top Z=0.145 м. Under=(0,-0.24,0.077), Side=(-0.033,-0.25,0.11) в Blender. Примерки фактической геометрии обвеса с backface culling: `_aek_hk416_attachments_20261003/fit`, все три HK416 + оба АЕК. Проверены M203/лазер/2x; другие оптические модели используют стандартный Scope origin и требуют игровой проверки.

`_aek_hk416_attachments_20261003/attachments-install.json`: applied=true, backup трёх файлов (items.lua, AEK971.lua, HK416.lua). АЕК: 4 слота/10 опций; HK416: 6/19. Offline Lua проверяет обе конфигурации АЕК с пятью прицелами, HK416 с Under/Side на всех стволах, создание/снятие M203 и сохранение гранаты. Generated sync: jazz 0 errors/12 warnings, assets 0/15; общий strict не PASS. Игра к установке уже закрыта, не запускалась. Игровая и editor приёмка этого обновления NOT_RUN.
