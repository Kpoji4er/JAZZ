# Локализация

## Назначение и эффект для игрока

Система связывает numeric localization ID из Lua и ModItem с языковыми CSV.
Русская таблица уже используется модом; рабочий каталог отделяет аудит ID от
будущего полного английского перевода.

## Владелец и runtime-слои

| Слой | Вклад |
|---|---|
| Установленная vanilla | Загружает базовую таблицу языка, затем таблицы активных модов; формат CSV — `ID,Text,Translation,VoiceActor,Context` в UTF-8 |
| CommonLib | В debug-сборке перехватывает `T` и сообщает об одном ID с разными исходными текстами; snapshot 26 июля 2026: 1.11 build 1056, commit `1adf9f232680d3b011248d180fd0ad1e609a8e2c` |
| JAZZ | Определяет строки в четырёх пакетах; `jazz/Russian.csv` перекрывает одноимённые ID базовой русской таблицы |

## Файлы реализации и load-state

- `Russian.csv` — loaded runtime для языка Russian через `metadata.loctables`;
- `English.csv` — объявлен metadata, но пока отсутствует и не считается
  реализованной локализацией;
- `Localization/Strings.csv` — development-only рабочий каталог;
- `Localization/Collisions.csv` — development-only отчёт коллизий;
- `scripts/localization/audit-localization.ps1` — development-only статический
  аудитор и контролируемый экспортёр;
- `items.lua` и пути из `metadata.code` четырёх пакетов — активные источники
  вызовов `T`; dormant Lua анализируется отдельно;
- `jazz-maps/Maps/` не входит в обзорный аудит.

## Модель данных и публичные IDs

`ID` является глобальным ключом перевода. Повтор ID допустим только с тем же
исходным текстом. Разные тексты под одним ID — коллизия независимо от пакета
или generated-представления.

`Localization/Strings.csv` хранит одну рабочую запись на ID. При обновлении
русская строка выбирается в порядке: `jazz/Russian.csv`, сохранённая ручная
строка каталога, русскоязычный исходник Lua, базовый `Game.csv`. Английская
строка из каталога и ручные заметки сохраняются.

## Runtime flow

1. JA3 загружает базовый `Game.csv` выбранного языка.
2. Моды обходятся в установленном порядке.
3. Подходящий `metadata.loctables` загружается поверх текущей таблицы.
4. `Translation` с тем же ID заменяет базовый перевод.

Текстовые поля и форматирующие теги не определяют ключ: ключом остаётся
numeric ID. Тем не менее `Text` нужен для аудита происхождения и должен
соответствовать строке в `T`.

## Зависимости и пересечения

Таблица мода может намеренно перекрывать перевод vanilla, но Lua не должен
переиспользовать vanilla ID для другого исходного текста. Аудитор сравнивает
активные JAZZ-вызовы как между собой, так и с переданным базовым `Game.csv`.
Файл `Russian.csv` считается более новым и приоритетным источником русского
перевода.

## Чек-лист проверки

- запустить аудитор с актуальным `Game.csv` и просмотреть
  `Localization/Collisions.csv`;
- устранить `active-id-collision`, `game-id-collision` и
  `russian-csv-collision`;
- проверить UTF-8, пять экспортных колонок и экранирование CSV;
- сохранить placeholders и пары форматирующих тегов;
- загрузить таблицу через Mod Editor, проверить панель сообщений и
  `TranslationChanged`;
- выполнить smoke-тест русского и английского интерфейса на clean start и
  после reload.

## Известные ограничения и долг

- текущий `Russian.csv` объявляет пять колонок, но содержит строки
  20-колоночного экспортного формата; аудитор читает их совместимо, однако
  файл следует нормализовать только контролируемым export/round-trip;
- English CSV пока отсутствует, несмотря на записи metadata;
- regex-аудит извлекает numeric ID из обычных строковых форм `T(...)` и
  `T{...}`; вычисляемые T-таблицы требуют runtime-проверки;
- содержимое `jazz-maps/Maps/` не проиндексировано.

## Контракт сопровождения

При добавлении или изменении локализуемой строки обновить код/ModItem,
запустить аудитор, устранить коллизии и обновить `Strings.csv`. Runtime CSV и
metadata изменять одной транзакцией через Mod Editor; английскую таблицу не
объявлять полной, пока экспорт не проходит без пропусков.
