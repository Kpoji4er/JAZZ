# Технический долг и рефакторинг

Документ фиксирует кандидатов на работу. Это не список файлов, которые можно удалять автоматически.

## Высокий приоритет

### Дробное пробитие: runtime и ammo UI

Модель: классы брони/атаки **1–5**, эффективный pen `GetAttackPenetrationClass` = `PenetrationClass + 0.1 × PenetrationBonus`. Канон — [armor-damage-wounds-will.md](systems/armor-damage-wounds-will.md), UI — [weapons-ammo-components.md](systems/weapons-ammo-components.md).

**Исправлено 2026-07-30 (static):** unit DR / `IsArmorPiercedBy` / object armor / ammo rollover сведены на одну формулу. Остаётся runtime smoke на границе класса (например pen 2.8 vs armor 3) и визуальная проверка tooltip FMJ 5.56 → **2.2**.

### Переопределения CommonLib

Одиннадцать функций и методов определяются и CommonLib, и JAZZ. Наиболее чувствительны AI selection, targeting, suspicion, UI actions и Run and Gun. Перед каждой задачей необходимо разрешить последнюю upstream-версию CLib; после любого изменения HEAD повторять трёхстороннее сравнение. Полный список находится в [override-matrix.md](override-matrix.md).

### Производительность vanilla (не закрыто модом)

Крупные sync-hard узкие места ванили (O(n²) `UpdateUnitsLOS`, полный AI DestLOS/LoF matrix, satellite Dijkstra без кэша) зафиксированы в [performance-vanilla-report.md](performance-vanilla-report.md). JAZZ закрывает только безопасные микро-оптимизации на своих overrides.

### Крупные копии vanilla

JAZZ содержит существенно изменённые версии больших игровых модулей AI, awareness, inventory, UI и satellite. Они могут незаметно отставать от исправлений новой версии JA3.

Безопасный рефакторинг:

1. Зафиксировать профильные smoke-тесты.
2. Выделить только реально заменяемые функции.
3. Сравнить каждую с текущей vanilla и CLib.
4. Удалять копию окружающего vanilla-кода только отдельными маленькими изменениями.
5. Не менять порядок загрузки одновременно.

### Зависимости пакетов

Metadata не отражает все фактические ссылки. Следует отдельно решить, какие пакеты действительно обязательны, затем добавить зависимости через Mod Editor и проверить загрузку неполной установки.

## Средний приоритет

### Дубли внутри основного пакета

Повторно определяются методы scrap/degrade и патрульная функция. Сначала нужно подтвердить последнюю работающую реализацию, затем оставить один источник истины без изменения результата.

### Загружаемые пустые файлы

Metadata содержит около 29 нулевых Lua-файлов, преимущественно FX/debug-заглушки. Их удаление из metadata изменит сериализованные данные и должно выполняться через Mod Editor отдельным коммитом.

### Незагружаемый код

На диске находятся `AimHiringScreen_Template.lua`, `PatrollingFix.lua`, `Savefix.lua` и другие файлы, которых нет в metadata. Нужно для каждого выбрать статус: подключить и протестировать, оставить как reference, перенести в архив истории или удалить после подтверждения.

`Savefix.lua` нельзя подключать без ревью: код миграции сохранений особенно чувствителен к частично инициализированным объектам.

### Локализация

Исправить ссылки на отсутствующие English CSV либо добавить полноценные таблицы. Не создавать пустые файлы-заглушки, потому что это формально объявит поддержку языка без перевода.

## Низкий приоритет и инфраструктура

### Окончания строк

Во всех репозиториях включён `core.autocrlf=true`, но `.gitattributes` отсутствует. Это создаёт массовый шум LF/CRLF. Добавление `.gitattributes` делать отдельным инфраструктурным изменением без одновременного форматирования Lua.

### Asset pipeline

Заменить абсолютные пути к FBX на воспроизводимую структуру источников и описать экспорт. Это потребует координации с владельцами исходных моделей; автоматическая замена путей недостаточна.

### Именование

Есть имена, различающиеся только регистром, например `PB`/`pb`, `Sig552`/`SIG552`, `SPAS12`/`Spas12`. На Windows они могут маскировать проблемы, которые проявятся в инструментах с чувствительной к регистру файловой системой.

## Предлагаемые этапы без изменения игрового поведения

1. Документация и правила работы.
2. Фиксация проверок и матрицы переопределений.
3. Репозиторная гигиена: `.gitattributes`, `.gitignore`, без перегенерации данных.
4. Удаление доказанно пустых загрузочных записей через Mod Editor.
5. Устранение одного внутреннего дубля за раз при сохранении последней реализации.
6. Сокращение крупных vanilla-копий небольшими проверяемыми изменениями.
7. Только после этого — функциональный или балансный рефакторинг.

Этапы 3–7 должны быть отдельными от текущего документационного изменения.
