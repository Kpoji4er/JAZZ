# Meshy: генерация брони JAZZ по исходным изображениям

Проверенный процесс на 2026-10-02. Область этого прохода: только Meshy и локальная выдача GLB/превью. Подгонка к телу, риг, экспорт HGE/AP и подключение в игру — отдельная работа по [character-element skill](../../skills/export-jazz-character-element/SKILL.md).

## Вход и запуск

Использовать установленный plugin `meshy-openai-plugin:meshy-3d-generation`, прочитать его SKILL.md и нужные references. Версия CLI этого прохода — **0.4.0**. Здесь работает Node + pnpm; отсутствие команды npm не означает отсутствия рабочего Meshy:

```powershell
pnpm.cmd dlx npm@11.6.2 exec --yes --package=meshy-cli@0.4.0 -- meshy auth status --format json --no-update-check
pnpm.cmd dlx npm@11.6.2 exec --yes --package=meshy-cli@0.4.0 -- meshy balance --output-schema v1 --format json --no-update-check
```

Продолжать при `authenticated: true`, `verified: true`. Не читать файл credentials и не копировать токены. Если нужен вход, `auth login --device`, показать владельцу URL и пользовательский код и дождаться **той же** сессии. Смена каталога повторного входа не требует. В первом опыте бесплатный тариф имел кредиты, но API генерацию отклонил; это не повод повторять create. После подключения подходящего тарифа API заработал.

## Выбор картинки

1. Приоритет — исходное изображение владельца или сохранённый оригинал, целый предмет без человека и UI. Проверить картинку глазами, а не по имени файла.
2. `ArmorIcons/Raw` содержит как подходящие оригиналы, так и **другие** предметы. `LeatherArmorb.png` — чешуйчатые доспехи, а наш `LeatherArmor` — округлый нагрудник на лямках; `Raw/Brigantine.png` также не равен шинной бригантине. Эти файлы нельзя подставлять только по названию.
3. Если текущую иконку заменили рендером кустарной модели, извлечь первоначальную из Git. Для этой партии использована ревизия `ae4e775a`, путь `ArmorIcons/<name>.png`. Не передавать бинарный PNG через текстовый PowerShell pipeline: сохранять `subprocess.check_output(['git','show',ref])` как bytes.
4. Записать путь, Git ref (если есть) и SHA256 в manifest. Мелкая иконка ограничивает восстановление деталей. Увеличение для контактного листа не добавляет исходной информации.
5. Несколько изображений — только согласованные ракурсы одного предмета. Не смешивать разные модели, комплектации и наши неудачные рендеры. Видимая на одном фото лицевая сторона не задаёт правильную спинку.

## Настройки, проверенные на 6Б3

`standard`, текстуры 2K, PBR, GLB; JSON через `--data @settings.json`:

```json
{
  "should_remesh": true,
  "topology": "triangle",
  "target_polycount": 15000,
  "image_enhancement": false
}
```

Для `standard` число полигонов передаётся этим JSON: CLI-флаг `--target-polycount` описан для `smart-topology`. Параметр `should_remesh` обязателен для встроенного упрощения standard. Цель приблизительна, реальное число проверять в GLB. `image_enhancement=false` сохраняет исходный дизайн без предварительной стилизации. У отдельного жилета не задавать A-позу персонажа.

Официальный контракт: [Image to 3D](https://docs.meshy.ai/en/api/image-to-3d), [Multi Image to 3D](https://docs.meshy.ai/en/api/multi-image-to-3d). Поведение текущего сервиса сверять с docs и `--help`, а не считать версию модели неизменной.

## Стоимость и жизненный цикл

Перед платной отправкой: `make '<reference>' --dry-run --output-schema v1 --format json --no-update-check` и `balance`. На этом проходе planner оценил textured image-to-3d в 30 кредитов за предмет. Это оценка; факт — `consumed_credits` завершённой задачи. Для других стадий сверять [официальные цены](https://docs.meshy.ai/en/api/pricing).

Последовательность для каждой модели:

1. `image-to-3d create --image-url '<reference>' --model-type standard --data '@<settings.json>' --should-texture true --enable-pbr true --texture-resolution 2k --target-formats glb --async --workspace '<workspace>'`.
2. Сохранить `result.submission.task_id` вместе с ресурсом `image-to-3d` **сразу**, до локальных последующих шагов. Для нескольких ракурсов ресурс `multi-image-to-3d` и `--image-urls`.
3. `project init --root '<workspace>' --name '<name>' --task-id '<id>' --task-type image-to-3d --workspace '<workspace>'`; получить `result.project_dir`.
4. `image-to-3d wait '<id>' --timeout 600 --project '<project_dir>' --stage generation --workspace '<workspace>'`. CLI сам опрашивает сервис. Timeout не означает провал и не разрешает новый create: повторять только wait того же ID.
5. `download --task-json '<project_dir>/task_<id>.json' --list`; выбрать GLB и доступное превью по реальным ключам. Скачать через CLI в тот же workspace, сохранить task JSON и metadata.
6. Посмотреть скачанное превью, показать владельцу; записать статус и реальные кредиты. Один рендер не доказывает хорошую спину, топологию, посадку и пригодность для JA3.

К каждой business-команде добавлять `--output-schema v1 --format json --no-update-check`. Не выводить в чат полный JSON с подписанными URL. При неоднозначной отправке не повторять платный create: проверить сохранённый stdout, локальный operation journal и список задач соответствующего ресурса. `--operation-id` защищает локальный повтор, но не является серверным ключом идемпотентности. Недостаток кредитов останавливает новые отправки.

## Опыт двух предыдущих задач

- 6Б3 по одному фото: плотная сетка и неоднозначная спинка. Второй проход по четырём сохранённым ракурсам с встроенным remesh дал **14 802 треугольника** за **30 кредитов**. Сохранять результат, а не генерировать заново для нового чата: `multi-image-to-3d / 01a0f974-6ad9-7565-80ab-cd96f804dfe3`.
- Конрад: standard без встроенного упрощения дал **994 778 треугольников**, один меш без скелета. Отдельный `remesh` существующей задачи с целью 20k дал **20 809 треугольников**, стоил **5 кредитов**; исходная генерация — **30**. Геометрия: `image-to-3d / 01a0f972-53ab-7235-88ad-6cbe08f16339`; remesh: `01a0f978-66af-7428-b9f1-9aad96a18ef2`.
- Новый LOD, формат или текстуры делать от существующей задачи. Не запускать повторную генерацию ради уменьшения сетки.
- Meshy не решает автоматически контакт лямок, веса JA3, пересечения с Body и игровые анимации. Успешный preview не закрывает runtime acceptance.

Скрипт [meshy_armor_batch.py](../../../docs/tools/meshy_armor_batch.py) сохраняет отправку до init и запрещает слепой повтор после сбоя. Рендеры после выдачи: `render_meshy_armor.py` запускается Blender в background с `-- --manifest <batch.json>`; `review_meshy_armor.py` создаёт `review.html`, `all-views.jpg`, `review-summary.json`. Это четыре ракурса скачанного GLB, не кадры игры. Бригантина в этом проходе получила terminal `server_error`, списание 0; владелец отдельно разрешил один повтор, новый ID `01a0f988-333f-7439-9fca-dc37310dd1bf` завершился успешно за 30 кредитов.

### Результат визуальной проверки партии

Пять задач SUCCEEDED, 150 кредитов, баланс 2970 → 2820. Blender: кираса 14979 tri, кольчуга 15348, бригантина 15443, шинная 15571, кожа 15158; все без рига. По четырём ракурсам кираса и шинная имеют объём. Кольчуга, бригантина и кожа почти плоские, с повтором переда на обороте; кожа также содержит лишнюю прямоугольную рамку. Эти три результата не приняты как полноценные носимые жилеты. Мелкая фронтальная иконка дала узнаваемый фасад, но не правильную пространственную конструкцию. Для будущего отдельно согласованного повтора нужны более информативные исходники/согласованные ракурсы; автоматически повторять платную генерацию нельзя. Рендеры и GLB сохранены без исправления геометрии.

Исправляющие геометрические промпты и границы API: `docs/design/meshy-armor-geometry-prompts.md`. У image-to-3d нет документированного geometry prompt; texture_prompt не заменяет его. Вариант text-to-3d сначала проверяется как untextured preview (оценка planner 20 кредитов), refine — лишь после проверки формы. Исходная картинка в text preview не передаётся; для сохранения дизайна нужен другой согласованный процесс подготовки ракурсов.

Требование владельца к дальнейшим промптам: явно указывать wearable armor for a video game character, standalone equipment for later skeletal rigging. Описывать объём под торс, зазор поверх одежды, реальные отверстия и расположение рукавов для движения рук. Не просить готовый скелет JA3 у генератора: корректная подгонка и skinning остаются отдельной работой. Разрешён один text preview Chainmail, задача `01a0f98e-cf42-77e9-b51d-221a9ee684c3`, параметры в `meshy_output/chainmail-game-armor-20261002/request.json`.

Результат text preview кольчуги: 20 кредитов, 15330 tri, один меш без рига. FAIL по отдельному снаряжению: вместо пустого жилета Meshy добавил голову и руки, несмотря на запрет. Полный промпт и выводы — `docs/design/meshy-armor-geometry-prompts.md`. Не считать текстовое описание надёжным исправлением геометрии без просмотра результата.

### Локальная проверка очистки Chainmail

Продолжение 2026-10-03: `finish_meshy_chainmail.py` установил, что оставшиеся 15 boundary рёбер принадлежат пяти оторванным микротреугольникам. Удалены только они, передние пластины локально выровнены по глубине; 14990 tri, ноль boundary/non-manifold рёбер, четыре проверенных отрезка проходов рукавов свободны. Исходник сохраняется отдельно. Контроль топологии не означает точную посадку на тело или готовность к анимации.

По присланному владельцем принятому reference выполнен **retexture / `01a0fe72-a211-74b6-b494-fa903c990e2e`**, SUCCEEDED, фактически **10 кредитов**. Рабочая папка `meshy_output/chainmail-textured-20261003`, проект `20261003_000857_chainmail-textured_01a0fe72`. Вход — исправленный локальный GLB, `--image-style-url reference.png --enable-original-uv false --enable-pbr true --texture-resolution 4k`. При изменении геометрии передавать локальную модель, а не task ID старой сетки. Выбирать один style input; обычный texture prompt не управляет геометрией. Контракт: [Retexture API](https://docs.meshy.ai/en/api/retexture).

Meshy нормализовал bounds и сократил сетку до 14984 tri. `package_meshy_retexture.py` восстановил исходный масштаб и центр; максимальное двунаправленное отклонение вершин 0.0000561 при высоте 1.88571. После диагностической сварки совпадающих UV-вершин — ноль boundary/non-manifold, одна компонента. Цвет/normal — 4096², metallic/roughness — 2048²: запрос 4K не гарантирует 4K для всех карт. Паковать исходные PNG, поскольку скачанный GLB содержит JPEG-копии. Итоговые `Chainmail_textured.blend` (packed textures), `Chainmail_textured.glb`, четыре PNG-карты, verification.json и шесть ракурсов сохраняются в проекте. Custom normals из GLB здесь сохранены для просмотра с normal map; перед HGE нужна отдельная подготовка/skin по штатному playbook. Это текстурированный кандидат без рига, не установленная JA3 entity.

`audit_meshy_armor.py`: исходный GLB содержит custom normals, 22521 вершин/15136 tri; после сварки строго совпадающих позиций — 7000 вершин, 391 boundary и 964 всего non-manifold рёбер. Это диагностическая сварка, не готовый экспорт. Простое сглаживание не устраняет дефекты и смягчает пластины. Voxel reconstruction + проходы рукавов дают локальный candidate 14995 tri, четыре проверенных отрезка проходов без пересечений. Остаётся 15 boundary рёбер; форма пластин мягкая. GLB/.blend и сравнение сохранены в `meshy_output/chainmail-cleanup-20261002/`; это частично очищенный кандидат, не финальная JA3-модель. Следующая качественная операция — отдельная чистая топология кольчужной оболочки и жёстких пластин, затем материал плетения на поверхности. Нельзя выдавать нулевую плату или исправление проходов за полную приёмку.
