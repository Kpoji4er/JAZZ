# Контракт CSV-локализации JAZZ

## Источники и приоритет

Для русского перевода применять приоритет:

1. корневой `Russian.csv` мода;
2. сохранённое поле `Russian` из `Localization/Strings.csv`;
3. кириллический исходник из активного `T(...)` или `T{...}`;
4. перевод совпадающего текста из базового русского `Game.csv`.

Для английского сохранять заполненное поле `English`. Если оно пусто, аудитор
может взять некириллический активный исходник или совпадающий английский `Text`
из базового `Game.csv`.

`Russian.csv` приоритетнее старого каталога и базовой игры. Приоритет источника
не отменяет коллизию ID: разные исходные тексты сначала требуется развести.

## Рабочий каталог

`Localization/Strings.csv` содержит столбцы:

| Столбец | Владелец | Назначение |
| --- | --- | --- |
| `ID` | аудитор | Numeric localization ID как строка цифр |
| `SourceText` | аудитор | Активный исходный текст или приоритетный override |
| `VanillaText` | аудитор | Английский `Text` того же ID из `Game.csv` |
| `Russian` | переводчик | Русский перевод |
| `English` | переводчик | Английский перевод |
| `Status` | аудитор | Состояния, разделённые `;` |
| `Context` | аудитор | Контекст строки |
| `Packages` | аудитор | Пакеты-потребители |
| `Locations` | аудитор | Файлы и строки потребителей |
| `Notes` | переводчик | Ручные примечания |

При `-UpdateCatalog` аудитор сохраняет заполненные `English` и `Notes`, а
`Russian.csv` имеет право заменить `Russian`. Остальные поля пересчитываются.

`Localization/Collisions.csv` содержит:

`ID,Kind,Text,ReferenceText,Locations`

Одна запись описывает один вариант конфликтующего текста.

## Статусы

- `active-id-collision` — один активный ID имеет разные исходные тексты;
- `game-id-collision` — активный текст не совпадает с vanilla-текстом того же ID;
- `russian-csv-collision` — `Russian.csv` содержит разные варианты одного ID;
- `russian-override` — строка взята из приоритетного `Russian.csv`;
- `new-id` — ID отсутствует в базовом `Game.csv`;
- `unreferenced-russian-override` — override не найден среди активных потребителей;
- `needs-russian` — поле `Russian` пусто;
- `needs-english` — поле `English` пусто;
- `ready` — другие статусы отсутствуют.

Статусы могут сочетаться через `;`. Любое вхождение `collision` блокирует
экспорт обоих языков.

## Формат runtime CSV

Игровая таблица имеет вид:

```csv
sep=,
ID,Text,Translation,VoiceActor,Context
```

Требования:

- кодировка UTF-8;
- ID хранится как строка цифр без округления;
- кавычка внутри поля удваивается;
- поле с запятой, кавычкой, CR или LF заключается в двойные кавычки;
- перенос строки внутри quoted field сохраняется;
- пустые `VoiceActor` и `Context` допустимы;
- один ID не должен обозначать разные исходные тексты.

Не считать количество физических строк файла количеством CSV-записей:
многострочный quoted field занимает несколько физических строк.

## Сохранность разметки

Перед экспортом сравнить перевод с `SourceText` и сохранить смысловые токены:

- `<...>` и другие игровые теги;
- `%...`, `{...}` и иные placeholder-ы;
- управляющие последовательности и явные переносы;
- имена параметров и технические идентификаторы.

Не переводить технический токен, если нет доказательства, что движок воспринимает
его как обычный текст. Расхождение пометить в `Notes`, если оно требует ручной
проверки.

## Граница автоматизации

Аудитор может читать четыре пакета, обновлять рабочий каталог и создавать
экспорт во временном месте. Он не должен автоматически перезаписывать runtime
`Russian.csv`/`English.csv`, менять localization ID в Lua или редактировать
generated data.

Изменение ID является изменением публичного контракта. До него проверить все
четыре пакета, владельца данных, `metadata.lua`, активные call sites и
совместимость. Generated ID менять только по процедуре Mod Editor и
`sync-jazz-generated-data`.
